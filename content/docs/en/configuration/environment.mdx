TimeWren is configured entirely through environment variables. This page lists every variable the code reads, grouped by purpose. Most self-hosted instances only need the [minimum configuration](#minimum-configuration) and, later, mail and storage.

## How variables are set

With the Docker Compose setup, put variables in a `.env` file next to `docker-compose.yml`. The `app` service loads that file (`env_file: .env`), and a few values are also passed explicitly by `docker-compose.yml`. After editing `.env`, run `docker compose up -d` to apply runtime variables. Compose recreates the containers whose configuration changed.

An empty value counts as "not set". `NEXT_PUBLIC_APP_URL=` falls back to its default, and a variable with an empty value behaves like one that is missing. Lines starting with `#` are comments, so `.env.example` ships with everything optional commented out.

### Build time and runtime

Variables named `NEXT_PUBLIC_*` are inlined into the browser bundle when the image is built. Changing them in `.env` afterwards has no effect on the prebuilt image. Three exceptions are read at runtime, with the build value only as a fallback: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_MARKETING_URL` and `NEXT_PUBLIC_BRAND`. The server reads them from its environment, and the browser gets them from `/runtime-config.js`, which the server generates per request. Marketing pages exist only in a build made with `BUILD_PROFILE=full`. The prebuilt image and the compose example use `selfhost`, which has none, so `NEXT_PUBLIC_MARKETING_URL` has no marketing pages to enable there.

Instance pages such as cookies, contact and account deletion use the running app URL and brand. Set `NEXT_PUBLIC_MARKETING_URL` explicitly to enable marketing on a self-hosted domain. Shared navigation and site metadata use the running marketing URL and brand. Editorial metadata and page copy describe TimeTrack Cloud, including its pricing and publisher. The public Cloud data processing agreement PDF is only available on TimeTrack Cloud.

The prebuilt image `ghcr.io/timewren/timewren` therefore has the other build-time variables fixed (for example `NEXT_PUBLIC_REALTIME_ENABLED`, `NEXT_PUBLIC_PLAUSIBLE_SCRIPT_URL` and the Sentry browser settings). To change those, build your own image with the matching build arguments, see [Install from source](/docs/install/from-source). The `Build time` column below says which variables this applies to.

The Content-Security-Policy headers are generated in `next.config.ts` from `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_MARKETING_URL`, `NEXT_PUBLIC_PLAUSIBLE_SCRIPT_URL`, `NEXT_PUBLIC_UMAMI_COLLECT_URL` and `NEXT_PUBLIC_UMAMI_SCRIPT_URL`, so they use the values present at build time.

> **Note:** Billing variables (`ALUNTA_API_KEY`, `STRIPE_SECRET_KEY`, `STORE_BILLING_ENABLED` and everything that goes with them) are inert for self-hosting. Billing is switched on only when at least one of those three is set. Without them every feature is open: there are no user or client limits, no trial that expires, no upgrade buttons and no payment mails.

## Minimum configuration

These five lines are enough to start an instance. Generate each secret with `openssl rand -hex 32`.

```dotenv
POSTGRES_PASSWORD=replace-with-a-random-secret
BETTER_AUTH_SECRET=replace-with-a-random-secret
ENCRYPTION_KEY=replace-with-64-hex-characters
CRON_SECRET=replace-with-a-random-secret
NEXT_PUBLIC_APP_URL=https://timewren.example.com
```

Without a mail transport, sign-up needs `REQUIRE_EMAIL_VERIFICATION=false` (see [Required](#required)). Configure [email](/docs/configuration/email) as soon as you can.

## Required

Compose refuses to start when `POSTGRES_PASSWORD`, `BETTER_AUTH_SECRET`, `ENCRYPTION_KEY` or `CRON_SECRET` is missing.

| Variable | Default | Required | Build time | Description |
| --- | --- | --- | --- | --- |
| `POSTGRES_PASSWORD` | none | yes | no | Password of the bundled PostgreSQL. Compose builds `DATABASE_URL` from it. It is only used when the database is first created: changing it later does not change the existing database. |
| `BETTER_AUTH_SECRET` | none | yes | no | Secret that signs sessions. Changing it logs everybody out. The container refuses to start without it. |
| `ENCRYPTION_KEY` | none | yes | no | AES-256-GCM key for stored tokens and credentials (calendar, accounting, webhooks). Exactly 64 hex characters. If you lose it, those integrations must be reconnected, so back it up. |
| `CRON_SECRET` | none | yes | no | Shared secret between the `cron` service and the app. Also needed for `/api/health?detail=1`. |
| `DATABASE_URL` | set by Compose | conditional | no | PostgreSQL connection string. Compose sets it to the bundled `db` service, so you do not set it yourself. Only needed with a different database or when running without Compose, for example `postgresql://user:password@host:5432/timetrack`. |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` | yes | no | The URL users open, without a trailing slash. Must match what the browser sees: use your `https://` domain behind a reverse proxy. See [URLs, hosts and brand](#urls-hosts-and-brand). |
| `REQUIRE_EMAIL_VERIFICATION` | `true` | no | no | Set to `false` (or `0`) to let people sign up and log in without a mail server. Only honoured while no mail transport is configured: with `RESEND_API_KEY` or `SMTP_HOST` set, the flag is ignored with a warning. Anyone who can reach the instance can then create an account, so remove it once mail works. |
| `ADMIN_EMAIL` | none | no | no | Instance admin addresses, comma separated. The account with a matching, verified address becomes admin. Empty: the oldest account becomes admin, but only while the instance has no admin. |

## Mail

Pick one transport: SMTP or Resend. Without either, the server logs skipped sends. Details and examples are in [Email](/docs/configuration/email).

The transport is chosen in this order: `MAIL_TRANSPORT` if set to a valid value, otherwise Resend when `RESEND_API_KEY` is set, otherwise SMTP when `SMTP_HOST` is set, otherwise log only.

| Variable | Default | Required | Build time | Description |
| --- | --- | --- | --- | --- |
| `MAIL_TRANSPORT` | automatic | no | no | `resend`, `smtp` or `log`. Forces the transport. `smtp` requires `SMTP_HOST`. |
| `SMTP_HOST` | none | conditional | no | SMTP server. Setting it selects SMTP unless `RESEND_API_KEY` is set or `MAIL_TRANSPORT` says otherwise. |
| `SMTP_PORT` | `587` | no | no | SMTP port. Port `465` uses implicit TLS. |
| `SMTP_SECURE` | `true` on port 465, else `false` | no | no | `true` for implicit TLS, `false` for STARTTLS. Empty uses the port rule. |
| `SMTP_USER` | none | no | no | SMTP username. Authentication is only used when this is set. |
| `SMTP_PASSWORD` | none | no | no | SMTP password. |
| `SMTP_FROM` | the sender chosen by the app | no | no | Sender address for all SMTP mails, for example `TimeWren <mail@timewren.example.com>`. Recommended with SMTP. |
| `RESEND_API_KEY` | none | conditional | no | API key for Resend. Setting it selects Resend. |
| `RESEND_FROM_EMAIL` | `TimeWren <noreply@<EMAIL_DOMAIN>>` | no | no | Default sender when sending through Resend. Use an address on a domain verified in Resend. |
| `FROM_EMAIL` | `TimeWren <noreply@<EMAIL_DOMAIN>>` | no | no | Sender of the task and notification mails. |
| `PERSONAL_FROM_EMAIL` | the default sender | no | no | Sender of personal lifecycle mails. |
| `PERSONAL_REPLY_TO_EMAIL` | none | no | no | Reply-To of personal lifecycle mails. Empty means no Reply-To header. |
| `RESEND_WEBHOOK_SECRET` | none | no | no | Svix signing secret for Resend delivery webhooks (`/api/webhooks/resend`). |
| `RESEND_AUDIENCE_ID` | none | no | no | Resend audience used for newsletter signups. |
| `ADMIN_NOTIFICATION_EMAIL` | none | no | no | Receives admin alerts and digests, comma separated. An address saved in the admin settings takes precedence. |
| `ADMIN_DISCORD_WEBHOOK_URL` | none | no | no | Discord webhook for admin alerts and in-app feedback. A URL saved in the admin settings takes precedence. |
| `FEEDBACK_TO_EMAIL` | none | no | no | Receives in-app feedback by mail. Empty: feedback goes to the Discord webhook only. |

## File storage

Uploads, email attachments and data exports need storage. Compose sets the local driver and mounts the `storage` volume. For S3-compatible storage (AWS, Hetzner, MinIO, R2) see [Storage](/docs/configuration/storage).

The driver is chosen like this: `STORAGE_DRIVER=local` wins; otherwise S3 is used when `S3_ENDPOINT` is set; otherwise there is no storage and uploads are switched off. The code never reads the value `s3` of `STORAGE_DRIVER`, so setting `S3_ENDPOINT` is what selects S3.

| Variable | Default | Required | Build time | Description |
| --- | --- | --- | --- | --- |
| `STORAGE_DRIVER` | `local` in Compose, otherwise none | no | no | `local` stores files on disk. Anything else falls through to the `S3_ENDPOINT` rule. |
| `STORAGE_LOCAL_PATH` | `./data/storage` (Compose: `/app/data/storage`) | no | no | Directory of the local driver. Compose sets it to the `storage` volume; change it only outside Compose. |
| `S3_ENDPOINT` | none | conditional | no | Endpoint of the S3-compatible service. Setting it selects S3 (path-style addressing is always used). |
| `S3_REGION` | `fsn1` | no | no | Region sent to the S3 client. Most S3-compatible services accept any value, but set the real one for AWS. |
| `S3_ACCESS_KEY_ID` | empty | conditional | no | S3 access key. |
| `S3_SECRET_ACCESS_KEY` | empty | conditional | no | S3 secret key. |
| `S3_BUCKET` | `timetrack` | no | no | Bucket name. |
| `S3_PREFIX` | empty | no | no | Optional namespace for all keys inside the bucket. |
| `EMAIL_ATTACHMENT_DIR` | `storage/email-attachments` | no | no | Directory that older email attachments are read from on disk. |
| `EMAIL_SYNC_STORE_ATTACHMENTS` | `false` | no | no | `true` uploads attachments from email-to-task sync to the configured storage. |
