TimeWren se configura por completo mediante variables de entorno. Esta página lista todas las variables que lee el código, agrupadas por finalidad. La mayoría de las instancias autoalojadas solo necesitan la configuración mínima y, más adelante, el correo y el almacenamiento.

## Cómo se definen las variables

Con la instalación de Docker Compose, pon las variables en un archivo `.env` junto a `docker-compose.yml`. El servicio `app` carga ese archivo (`env_file: .env`) y `docker-compose.yml` pasa explícitamente algunos valores más. Tras editar `.env`, ejecuta `docker compose up -d` para aplicar las variables de ejecución. Compose recrea los contenedores cuya configuración ha cambiado.

Un valor vacío cuenta como "no definido". `NEXT_PUBLIC_APP_URL=` vuelve a su valor por defecto, y una variable con valor vacío se comporta como una que no existe. Las líneas que empiezan por `#` son comentarios, por eso `.env.example` incluye todo lo opcional comentado.

### Compilación y ejecución

Las variables `NEXT_PUBLIC_*` se incrustan en el bundle del navegador cuando se construye la imagen. Cambiarlas después en `.env` no tiene efecto sobre la imagen ya construida. Hay tres excepciones que se leen en tiempo de ejecución, y el valor de compilación solo sirve como respaldo: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_MARKETING_URL` y `NEXT_PUBLIC_BRAND`. El servidor las lee de su entorno y el navegador las recibe de `/runtime-config.js`, que el servidor genera en cada petición. Las páginas de marketing solo existen en una compilación con `BUILD_PROFILE=full`. La imagen precompilada y el ejemplo de Compose usan `selfhost`, que no tiene ninguna, así que `NEXT_PUBLIC_MARKETING_URL` no tiene allí páginas de marketing que activar.

Las páginas de la instancia, como las de cookies, contacto y eliminación de cuenta, usan la URL y la marca de la aplicación en ejecución. Configura `NEXT_PUBLIC_MARKETING_URL` explícitamente para activar el marketing en un dominio autoalojado. La navegación compartida y los metadatos del sitio usan la URL de marketing y la marca en ejecución. Los metadatos editoriales y los textos de las páginas describen TimeTrack Cloud, incluidos sus precios y su editor. El PDF público del acuerdo de tratamiento de datos solo está disponible en TimeTrack Cloud.

Por eso, en la imagen precompilada `ghcr.io/timewren/timewren` las demás variables de compilación vienen fijadas (por ejemplo `NEXT_PUBLIC_REALTIME_ENABLED`, `NEXT_PUBLIC_PLAUSIBLE_SCRIPT_URL` y los ajustes de Sentry para el navegador). Para cambiarlas, construye tu propia imagen con los argumentos de compilación correspondientes, consulta [Instalar desde el código fuente](/es/docs/install/from-source). La columna `Build time` de las tablas siguientes indica a qué variables afecta esto.

Las cabeceras Content-Security-Policy se generan en `next.config.ts` a partir de `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_MARKETING_URL`, `NEXT_PUBLIC_PLAUSIBLE_SCRIPT_URL`, `NEXT_PUBLIC_UMAMI_COLLECT_URL` y `NEXT_PUBLIC_UMAMI_SCRIPT_URL`, así que usan los valores presentes en el momento de la compilación.

> **Nota:** Las variables de facturación (`ALUNTA_API_KEY`, `STRIPE_SECRET_KEY`, `STORE_BILLING_ENABLED` y todo lo que va con ellas) no hacen nada en el autoalojamiento. La facturación solo se activa cuando se define al menos una de esas tres. Sin ellas, todas las funciones están abiertas: no hay límites de usuarios ni de clientes, ninguna prueba que caduque, ningún botón de mejora de plan y ningún correo de pago.

## Configuración mínima

Estas cinco líneas bastan para arrancar una instancia. Genera cada secreto con `openssl rand -hex 32`.

```dotenv
POSTGRES_PASSWORD=replace-with-a-random-secret
BETTER_AUTH_SECRET=replace-with-a-random-secret
ENCRYPTION_KEY=replace-with-64-hex-characters
CRON_SECRET=replace-with-a-random-secret
NEXT_PUBLIC_APP_URL=https://timewren.example.com
```

Sin un transporte de correo, el registro necesita `REQUIRE_EMAIL_VERIFICATION=false` (consulta la sección Obligatorias). Configura el [correo electrónico](/es/docs/configuration/email) en cuanto puedas.

## Obligatorias

Compose se niega a arrancar si falta `POSTGRES_PASSWORD`, `BETTER_AUTH_SECRET`, `ENCRYPTION_KEY` o `CRON_SECRET`.

| Variable | Default | Required | Build time | Description |
| --- | --- | --- | --- | --- |
| `POSTGRES_PASSWORD` | ninguno | sí | no | Contraseña del PostgreSQL incluido. Compose construye `DATABASE_URL` a partir de ella. Solo se usa cuando se crea la base de datos por primera vez: cambiarla después no modifica la base de datos existente. |
| `BETTER_AUTH_SECRET` | ninguno | sí | no | Secreto que firma las sesiones. Al cambiarlo se cierra la sesión de todos. El contenedor se niega a arrancar sin él. |
| `ENCRYPTION_KEY` | ninguno | sí | no | Clave AES-256-GCM para los tokens y credenciales almacenados (calendario, contabilidad, webhooks). Exactamente 64 caracteres hexadecimales. Si la pierdes, habrá que volver a conectar esas integraciones, así que haz una copia de seguridad. |
| `CRON_SECRET` | ninguno | sí | no | Secreto compartido entre el servicio `cron` y la aplicación. También es necesario para `/api/health?detail=1`. |
| `DATABASE_URL` | lo define Compose | condicional | no | Cadena de conexión de PostgreSQL. Compose la apunta al servicio `db` incluido, así que no tienes que definirla tú. Solo hace falta con otra base de datos o al ejecutar sin Compose, por ejemplo `postgresql://user:password@host:5432/timetrack`. |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` | sí | no | La URL que abren los usuarios, sin barra final. Debe coincidir con lo que ve el navegador: usa tu dominio `https://` detrás de un reverse proxy. Consulta la sección URLs, hosts y marca. |
| `REQUIRE_EMAIL_VERIFICATION` | `true` | no | no | Ponla en `false` (o `0`) para permitir registrarse e iniciar sesión sin servidor de correo. Solo se respeta mientras no haya un transporte de correo configurado: con `RESEND_API_KEY` o `SMTP_HOST` definidos, el indicador se ignora con un aviso. Cualquiera que pueda acceder a la instancia puede entonces crear una cuenta, así que quítala cuando el correo funcione. |
| `ADMIN_EMAIL` | ninguno | no | no | Direcciones de administrador de la instancia, separadas por comas. La cuenta con una dirección coincidente y verificada pasa a ser administradora. Si está vacía: la cuenta más antigua pasa a ser administradora, pero solo mientras la instancia no tenga ninguno. |

## Correo

Elige un transporte: SMTP o Resend. Sin un transporte, el servidor registra los envíos omitidos. Encontrarás detalles y ejemplos en [Correo electrónico](/es/docs/configuration/email).

El transporte se elige en este orden: `MAIL_TRANSPORT` si tiene un valor válido; si no, Resend cuando `RESEND_API_KEY` está definida; si no, SMTP cuando `SMTP_HOST` está definida; si no, solo log.

| Variable | Default | Required | Build time | Description |
| --- | --- | --- | --- | --- |
| `MAIL_TRANSPORT` | automático | no | no | `resend`, `smtp` o `log`. Fuerza el transporte. `smtp` requiere `SMTP_HOST`. |
| `SMTP_HOST` | ninguno | condicional | no | Servidor SMTP. Al definirla se elige SMTP, salvo que `RESEND_API_KEY` esté definida o `MAIL_TRANSPORT` indique otra cosa. |
| `SMTP_PORT` | `587` | no | no | Puerto SMTP. El puerto `465` usa TLS implícito. |
| `SMTP_SECURE` | `true` en el puerto 465; si no, `false` | no | no | `true` para TLS implícito, `false` para STARTTLS. Vacía aplica la regla del puerto. |
| `SMTP_USER` | ninguno | no | no | Nombre de usuario SMTP. La autenticación solo se usa si está definida. |
| `SMTP_PASSWORD` | ninguno | no | no | Contraseña SMTP. |
| `SMTP_FROM` | el remitente elegido por la aplicación | no | no | Dirección del remitente de todos los correos SMTP, por ejemplo `TimeWren <mail@timewren.example.com>`. Recomendada con SMTP. |
| `RESEND_API_KEY` | ninguno | condicional | no | Clave de API de Resend. Al definirla se elige Resend. |
| `RESEND_FROM_EMAIL` | `TimeWren <noreply@<EMAIL_DOMAIN>>` | no | no | Remitente por defecto al enviar con Resend. Usa una dirección de un dominio verificado en Resend. |
| `FROM_EMAIL` | `TimeWren <noreply@<EMAIL_DOMAIN>>` | no | no | Remitente de los correos de tareas y de notificaciones. |
| `PERSONAL_FROM_EMAIL` | el remitente por defecto | no | no | Remitente de los correos personales del ciclo de vida. |
| `PERSONAL_REPLY_TO_EMAIL` | ninguno | no | no | Reply-To de los correos personales del ciclo de vida. Vacía significa que no hay cabecera Reply-To. |
| `RESEND_WEBHOOK_SECRET` | ninguno | no | no | Secreto de firma de Svix para los webhooks de entrega de Resend (`/api/webhooks/resend`). |
| `RESEND_AUDIENCE_ID` | ninguno | no | no | Audiencia de Resend usada para las altas en el boletín. |
| `ADMIN_NOTIFICATION_EMAIL` | ninguno | no | no | Recibe las alertas y resúmenes de administración, separadas por comas. Una dirección guardada en los ajustes de administración tiene prioridad. |
| `ADMIN_DISCORD_WEBHOOK_URL` | ninguno | no | no | Webhook de Discord para las alertas de administración y los comentarios dentro de la aplicación. Una URL guardada en los ajustes de administración tiene prioridad. |
| `FEEDBACK_TO_EMAIL` | ninguno | no | no | Recibe por correo los comentarios enviados desde la aplicación. Vacía: los comentarios solo van al webhook de Discord. |

## Almacenamiento de archivos

Las subidas, los adjuntos de correo y las exportaciones de datos necesitan almacenamiento. Compose establece el driver local y monta el volumen `storage`. Para almacenamiento compatible con S3 (AWS, Hetzner, MinIO, R2) consulta [Almacenamiento](/es/docs/configuration/storage).

El driver se elige así: gana `STORAGE_DRIVER=local`; si no, se usa S3 cuando `S3_ENDPOINT` está definida; si no, no hay almacenamiento y las subidas quedan desactivadas. El código nunca lee el valor `s3` de `STORAGE_DRIVER`, así que lo que selecciona S3 es definir `S3_ENDPOINT`.

| Variable | Default | Required | Build time | Description |
| --- | --- | --- | --- | --- |
| `STORAGE_DRIVER` | `local` en Compose; si no, ninguno | no | no | `local` guarda los archivos en disco. Cualquier otro valor pasa a la regla de `S3_ENDPOINT`. |
| `STORAGE_LOCAL_PATH` | `./data/storage` (Compose: `/app/data/storage`) | no | no | Directorio del driver local. Compose lo apunta al volumen `storage`; cámbialo solo fuera de Compose. |
| `S3_ENDPOINT` | ninguno | condicional | no | Endpoint del servicio compatible con S3. Al definirlo se selecciona S3 (siempre se usa direccionamiento de tipo path). |
| `S3_REGION` | `fsn1` | no | no | Región que se envía al cliente S3. La mayoría de los servicios compatibles con S3 aceptan cualquier valor, pero indica la real para AWS. |
| `S3_ACCESS_KEY_ID` | vacío | condicional | no | Clave de acceso de S3. |
| `S3_SECRET_ACCESS_KEY` | vacío | condicional | no | Clave secreta de S3. |
| `S3_BUCKET` | `timetrack` | no | no | Nombre del bucket. |
| `S3_PREFIX` | vacío | no | no | Espacio de nombres opcional para todas las claves dentro del bucket. |
| `EMAIL_ATTACHMENT_DIR` | `storage/email-attachments` | no | no | Directorio del que se leen en disco los adjuntos de correo más antiguos. |
| `EMAIL_SYNC_STORE_ATTACHMENTS` | `false` | no | no | `true` sube al almacenamiento configurado los adjuntos de la sincronización de correo a tarea. |
